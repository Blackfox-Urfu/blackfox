# Классификация сообщений из Telegram

---

## 1. Цель проекта

Создрание инструмента для автоматической сортировки рекламных и просто нежелательных сообщений внутри телеграм для обычных пользователей и владельцев каналов-чатов.

---

## 2. Основные этапы проекта

### 2.1. Загрузка данных
- Данные представляют собой файлы JSON с текстами рекламных и нерекламных сообщений.
- Сообщения извлекаются из структур файлов и подготавливаются для дальнейшей обработки.

### 2.2. Предобработка данных
- Очистка текста от ненужных символов (переносов строк, перенос строки, форматирование и т.д.).
- Выделение текста из json файла.

### 2.3. Формирование выборок
- Каждому сообщению присваивается метка:
  - `1` — рекламное сообщение.
  - `0` — нерекламное сообщение.
- Объединение данных в единый набор для обучения и тестирования.

### 2.4. Разделение данных
- **Обучающая выборка**: используется для тренировки моделей.
- **Тестовая выборка**: применяется для проверки точности классификации.

### 2.5. Очистка данных 
- Удаление стоп слов, лемматизация ([nltk](https://www.nltk.org/),[pymorphy2](https://github.com/pymorphy2/pymorphy2))

### 2.6. Векторизация текста
- Преобразование текста в числовой вид с помощью [TF-IDF (term frequency–inverse document frequency)](https://ru.wikipedia.org/wiki/TF-IDF).

### 2.7. Балансировка данных
- Для борьбы с дисбалансом между рекламными и нерекламными сообщениями применяется метод [SMOTE(Synthetic Minority Over-sampling Technique)](https://www.jair.org/index.php/jair/article/view/10302).

### 2.8. Обучение моделей

В проекте рассматриваются(пока не определили) к применению три основные модели машинного обучения: **Случайный лес**, **Градиентный бустинг**, и **Нейронная сеть**. Ниже описаны их особенности и подходы к обучению.

#### **[Случайный лес](https://arxiv.org/pdf/1407.7502)**:

- Построен на ансамбле деревьев решений, обучаемых на случайных подвыборках данных.
- Гиперпараметры (количество деревьев, глубина, минимальное число образцов для разбиения и др.) оптимизируются с помощью Optuna (Оптимизация Байеса - поиск лучших параметров на основе исторических оценок точности).
- Для предотвращения переобучения используется ограничение на глубину деревьев.
- Устойчив к шуму и дисбалансу данных благодаря bagging-методу(независимое обучение нескольких моделей по случайным данным с последующим объединением данных).


#### **[Градиентный бустинг](https://export.arxiv.org/pdf/2410.05623)**:

- Модель построена с использованием библиотеки **[CatBoost](https://arxiv.org/pdf/1810.11363)**.
- Используется подход оптимизации гиперпараметров с помощью библиотеки **Optuna**, включая такие параметры, как:
    - **Количество итераций**: количество проходов бустинга.
    - **Глубина деревьев**: максимальная глубина, используемая в деревьях.
    - **Скорость обучения**: влияет на размер корректировок весов деревьев.
    - **L2-регуляризация**:  параметр регуляризации для предотвращения переобучения.
    - **Функция потерь**: выбор из категорий `MultiClass` и `MultiClassOneVsAll`.
- Для обучения и прогнозирования используется **ускорение на GPU**.
- Данные предварительно векторизуются (преобразование данных в числовые векторы) с помощью **TF-IDF**, а затем балансируются с использованием **SMOTE** для борьбы с дисбалансом классов.
- Финальная модель обучается на оптимальных гиперпараметрах, полученных в процессе оптимизации, и оценивается с использованием метрик `accuracy`, `classification_report`, и `confusion_matrix`.

#### **Нейронная сеть с использованием [TensorFlow](https://www.tensorflow.org/tutorials?hl=ru) и [Optuna](https://github.com/optuna/optuna?tab=readme-ov-file)**:

- Архитектура представлена многослойным персептроном с `Dense`-слоями.
- Регуляризация достигается с помощью **Dropout** (выключение определенной доли нейронов во время обучения для предотвращения переобучения).
- Для токенизации текста используется `Tokenizer` из `tensorflow.keras.preprocessing.text`.
- Векторизация и нормализация текстовых данных проводятся с помощью `pad_sequences`.
- Гиперпараметры, включая количество слоев, dropout, размер batch, скорость обучения и др., оптимизируются с помощью **Optuna**.
- Для предотвращения переобучения применяется метод **ранней остановки** (`EarlyStopping`) во время обучения, если в процессе не видно улучшений
- Используется взвешивание классов для борьбы с дисбалансом.

Каждая из моделей обучается и тестируется с использованием данных, полученных из JSON-файлов экспорта историй наших телеграмм каналов с собранными данными. Далее проводится их векторизация, балансировка и оптимизация гиперпараметров для достижения наилучшего результата на тестовых данных.


### 2.8. Оценка качества моделей
- **Метрики**:
  - Точность (`accuracy`).
  - Отчет классификации (`classification report`).
  - Матрица ошибок (`confusion matrix`).

### 2.9. Сохранение модели
- Лучшая модель и векторизатор сохраняются на диск для использования в будущем.

## **3. Архитектура**

Архитектура может быть адаптирована в зависимости от объема данных, частоты обработки и других требований проекта.

#### **3.1 Сбор данных**
- **Источник данных**: API Telegram (Telegram Bot API / Telegram Client API) для получения сообщений из чатов и каналов.
- **Модуль обработки сообщений**: Обработка и предварительная очистка текста (удаление HTML-тегов, эмодзи, ссылок и т. д.).
- **Хранилище данных**: 
  - Хранение сырых сообщений (например, NoSQL, MongoDB или DynamoDB).
  - Логирование метаданных сообщений (например, дата, отправитель, ID чата).


#### **3.2 Предобработка текста**
- **Очистка текста**: Удаление стоп-слов, токенизация, лемматизация (использование библиотек, таких как NLTK, spaCy).
- **Векторизация текста**: TF-IDF или другие методы представления текста (например, word embeddings — Word2Vec, FastText, BERT).


#### **3.3 Модель классификации**
- **Модель машинного обучения/нейронной сети**: 
  - Алгоритмы: Random Forest, Gradient Boosting (например, CatBoost), либо нейросети (LSTM/Transformer).
  - Хранилище модели: Обученная модель хранится в формате `.pkl` для catboost и scikit(random forest) или `keras` для tensorflow, поддерживаемых библиотекой, форматах.


#### **3.4 Обработка запросов**
- **REST API**:
  - Сервер, который принимает сообщения и возвращает вероятность рекламы (например, FastAPI, Flask).
  - Эндпоинты:
    - `POST /classify` — классификация одного сообщения.
    - `POST /batch-classify` — пакетная классификация сообщений.


#### **3.5 Хранение и управление данными**
- **База данных**:
  - NoSQL (MongoDB) или SQL (PostgreSQL) для хранения:
    - Сообщений.
    - Результатов классификации (рекламное/нерекламное сообщение).
    - Истории обработки запросов.
- **Файловое хранилище** (например, Amazon S3): Для хранения логов, обученных моделей, словарей.


#### **3.6 Фильтрация сообщений**
- **Модуль фильтрации**: 
  - Получает классифицированные сообщения.
  - Предоставляет возможность:
    - Удаления/скрытия рекламных сообщений.
    - Отправки их в отдельный чат/лог.


#### **3.7 Обучение и дообучение модели**
- **Периодическое обновление модели**:
  - Сбор новых данных (актуализация).
  - Дообучение модели на новых данных.
- **Модуль A/B тестирования**:
  - Проверка эффективности новых моделей на реальных данных.


#### **3.8 Визуализация и мониторинг**
- **Панель администратора**:
  - Веб-интерфейс для мониторинга работы системы.
  - Метрики классификации (accuracy, precision, recall, F1-score).
  - История запросов.
- **Мониторинг и алерты**:
  - Инструменты: Prometheus, Grafana.
  - Логи и алерты на ошибки или снижение производительности.


### **3.9 Варианты архитектуры развертывания**
1. **Локальное развертывание**:
   - Подходит для небольших экспериментов и разработки.
   - Инструменты: Docker, локальная база данных.

2. **Облачное развертывание**:
   - Использование облачных платформ (AWS, GCP, Azure) для масштабируемости.
   - Хранение данных в облачных сервисах (S3, BigQuery).

3. **Гибридное развертывание**:
   - Предобработка данных локально, хранение и вычисления в облаке.
   - Использование API для взаимодействия между компонентами.

## 4. Описание Telegram-бота

### 4.1. Функционал
#### Для btb
1. Прием входящих сообщений из чата.
2. Классификация сообщений (реклама/нереклама).
3. Автоматическая модерация:
   - Удаление рекламных сообщений.
   - Отправка предупреждений пользователям.
4. Генерация отчетов для администраторов:
   - Количество рекламных сообщений.
   - Подробная статистика.
#### Для btc 
1. Парсинг постов из канала.
2. Классификация сообщений (реклама/нереклама).
3. Автоматическая модерация:
	* Скрытие сообщений
	* Сохранение в статистику 
### 4.2. Настройки
- Включение/выключение модерации.
- Настройка чувствительности классификатора.
- Управление списком разрешенных тем и ключевых слов.

### 4.3. Взаимодействие с ботом
- Команды:
  - `/start` — запуск бота.
  - `/status` — проверка состояния бота.
  - `/report` — запрос отчета о модерации.
