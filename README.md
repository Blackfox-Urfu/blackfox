## 1. Введение

### 1.1. Актуальность проблемы

Мессенджер Telegram завоевал огромную популярность как средство быстрой и безопасной коммуникации, а также как платформа для распространения информации через каналы и группы. Однако, наряду с ценным контентом, пользователи все чаще сталкиваются с агрессивной рекламой и нежелательными материалами, включая контент для взрослых (NSFW). Такой "визуальный шум" не только отвлекает, но и может создавать дискомфорт, особенно в публичных пространствах. Ручная фильтрация неэффективна и трудоемка. В связи с этим, разработка интеллектуальных инструментов для автоматической классификации и фильтрации контента является актуальной задачей, направленной на улучшение пользовательского опыта.

### 1.2. Цель и задачи проекта

**Цель проекта:** Создать инструмент для автоматической фильтрации текстовой рекламы и обнаружения NSFW-контента (в текстовых сообщениях и на изображениях, включая аватарки) в Telegram, который повысит удобство использования мессенджера, уберёт визуальный шум и повысит безопасность пользователей.

**Задачи проекта:**

1.  Разработать методы сбора и подготовки данных из Telegram.
2.  Подготовить и разметить наборы данных для обучения моделей машинного обучения.
3.  Разработать и обучить модель на основе нейронной сети PyTorch для классификации текстовых сообщений (реклама/не реклама).
4.  Разработать и обучить модель на основе архитектуры ResNet для классификации изображений (NSFW/SFW).
5.  Реализовать серверное API на FastAPI для предоставления доступа к обученным моделям.
6.  Создать расширение для браузера Chrome, использующее API для фильтрации контента в веб-версии Telegram.
7.  Обеспечить возможность развертывания и эксплуатации ключевых компонентов системы.

### 1.3. Обзор решения

Предлагаемая система представляет собой многокомпонентное решение:
*   **Подсистема сбора данных:** Включает модуль `listener.py` для автоматизированного сбора сообщений через TDLib и использование стандартных функций экспорта Telegram для получения данных в формате JSON. Скрипт `merge.py` используется для предобработки и объединения JSON-дампов.
*   **Подсистема обучения моделей:**
    *   `torch_text.py`: Отвечает за обучение нейросетевой модели (MLP) на PyTorch для классификации текста, используя TF-IDF векторизацию и оптимизацию гиперпараметров с Optuna.
    *   `resnet_learn_slut_detector.py`: Используется для обучения модели ResNet34 для классификации изображений на NSFW/SFW контент, с применением техник аугментации и балансировки классов.
*   **Сервер API (`main.py`):** Реализован на FastAPI, предоставляет HTTP-эндпоинты для классификации текста и изображений, используя обученные модели.
*   **Клиентское приложение (Расширение для браузера Chrome):** Интегрируется с веб-версией Telegram, отправляет контент на сервер API для анализа и применяет выбранный пользователем способ фильтрации.

### 1.4. Ценность для пользователя

Рекламные сообщения, спам и нежелательный контент являются распространенными раздражителями в интернете, снижающими комфорт использования платформ. Пользователи стремятся избавиться от этого "визуального шума" и оградить себя от потенциально неприемлемых материалов. Данный проект предлагает решение, которое:
*   **Уменьшает количество навязчивой рекламы:** Освобождает ленту от избыточных коммерческих предложений.
*   **Фильтрует NSFW-контент:** Повышает безопасность и комфорт при использовании Telegram, особенно в публичных чатах, каналах и при просмотре аватарок пользователей, предотвращая случайный просмотр неподходящих материалов.
*   **Повышает удобство использования:** Делает взаимодействие с мессенджером более целенаправленным и приятным.

## 2. Архитектура системы

### 2.1. Общая архитектура

Архитектура проекта является многоуровневой и модульной, что обеспечивает гибкость разработки и развертывания (см. Приложение А: UML-диаграмма системы).

1.  **Уровень сбора и подготовки данных:**
    *   Используется встроенная функция экспорта чатов из Telegram Desktop для получения истории сообщений в формате JSON.
    *   Скрипт `merge.py` обрабатывает и объединяет эти JSON-файлы.
    *   Скрипт `listener.py` (использующий TDLib) служит для потенциального автоматизированного сбора больших объемов данных и их сохранения в CSV-файлы для последующего анализа и разметки.
2.  **Уровень обучения моделей (локальная среда разработчика):**
    *   Скрипты `torch_text.py` и `resnet_learn_slut_detector.py` используют подготовленные датасеты (текстовые из `data/reklama`, `data/nereklama`; изображения из `data/slut`, `data/regular`) для обучения моделей.
    *   Артефакты обучения (веса моделей, конфигурации, векторизаторы) сохраняются в директорию `model`.
3.  **Уровень предоставления сервиса (API-сервер):**
    *   `main.py`, реализованный на FastAPI, разворачивается на удаленном сервере.
    *   API-сервер загружает обученные модели из директории `model` и предоставляет HTTP-эндпоинты для классификации.
4.  **Уровень клиента (браузерное расширение):**
    *   Расширение для Chrome взаимодействует с API-сервером, отправляя данные для анализа.
    *   На основе полученных от сервера классификаций, расширение модифицирует отображение контента в веб-интерфейсе Telegram.

### 2.2. Взаимодействие компонентов

*   Данные, экспортированные из Telegram Desktop, обрабатываются `merge.py`. Дополнительные данные могут собираться `listener.py`.
*   Скрипты обучения (`torch_text.py`, `resnet_learn_slut_detector.py`) используют эти данные для тренировки моделей локально.
*   Сервер API (`main.py`) загружает обученные модели и ожидает запросы.
*   Расширение для Chrome (`background.js`) отправляет текстовые данные и, потенциально, ссылки на изображения (или сами изображения) на соответствующие эндпоинты API-сервера.
*   `content.js` (часть расширения) применяет изменения к DOM веб-страницы Telegram на основе ответов сервера.
*   `popup.js` позволяет пользователю настраивать параметры фильтрации и управлять списком исключенных каналов.

## 3. Описание компонентов системы

### 3.1. Сбор и подготовка данных

#### 3.1.1. Модуль сбора данных (`listener.py`)

Скрипт `listener.py` предназначен для автоматизированного сбора текстовых сообщений из Telegram и их первичной классификации/сохранения. В текущем рабочем процессе проекта он в большей степени служит как инструмент для накопления данных, которые могут быть использованы для дальнейшего дообучения моделей.
*   **Интеграция с TDLib:** Использует `TDLib` для взаимодействия с Telegram API.
*   **Авторизация:** Поддерживает полный процесс авторизации.
*   **Сбор сообщений:** Может получать историю чатов и новые сообщения.
*   **Дедупликация:** Применяет `ScalableBloomFilter` для избежания дублирования сообщений.
*   **Потенциальная классификация и сохранение:** В коде предусмотрена отправка сообщений на внешний API для классификации и проверка на рекламу по ключевым словам. Сообщения сохраняются в CSV-файлы (`advertisements.csv`, `regular_messages.csv`) батчами, с указанием текста, хеша, результата классификации (если получен), ID отправителя, информации о чате и даты.

#### 3.1.2. Модуль слияния данных (`merge.py`)

Этот скрипт используется для обработки JSON-файлов, полученных путем экспорта данных из Telegram.
*   **Обработка JSON:** Читает файлы `result.json` из директорий с рекламными и нерекламными данными.
*   **Извлечение и дедупликация текста:** Аккуратно извлекает текстовое содержимое сообщений и удаляет дубликаты, чтобы обеспечить уникальность постов в обучающих выборках.
*   **Сохранение:** Формирует и сохраняет очищенные данные в файлы `reklama_data.json` и `nereklama_data.json`.

#### 3.1.3. Экспорт данных из Telegram Desktop

Основным методом сбора данных для обучения моделей в текущей итерации проекта является использование встроенной функции экспорта чатов в клиенте Telegram Desktop. Это позволяет получить структурированные данные в формате JSON, которые затем обрабатываются скриптом `merge.py`.

### 3.2. Обучение моделей машинного обучения

#### 3.2.1. Классификатор текста на основе PyTorch (`torch_text.py`)

Этот скрипт реализует полный конвейер для обучения модели классификации текстов (реклама/не реклама).
*   **Данные и предобработка:**
    *   Загружает данные из JSON-файлов, обработанных `merge.py`.
    *   Тексты очищаются, данные делятся на обучающую, валидационную и тестовую выборки.
*   **Векторизация TF-IDF:**
    *   `TfidfVectorizer` из `scikit-learn` преобразует тексты в числовые векторы.
    *   Используются русские стоп-слова, N-граммы (1,2), настроены `min_df` и `max_df`.
*   **Модель (`AdvancedTextClassifier`):**
    *   Применяется многослойный перцептрон (MLP), определенный в `model_architecture.py` (и внутри самого `torch_text.py`). Архитектура включает настраиваемое число слоев, нейронов, функции активации, Dropout и Batch Normalization.
*   **Оптимизация гиперпараметров с Optuna:**
    *   Optuna используется для автоматического подбора оптимальной конфигурации MLP (архитектура, learning rate, batch size, dropout и т.д.) с целью максимизации F1-score на валидационной выборке.
*   **Обучение:**
    *   Применяется `WeightedRandomSampler` для балансировки классов в `DataLoader`.
    *   Используется `CrossEntropyLoss` и оптимизаторы (AdamW или RMSprop), подобранные Optuna.
    *   Реализован механизм ранней остановки.
*   **Оценка и сохранение:**
    *   Финальная модель обучается на объединенных данных (train+validation) с лучшими гиперпараметрами.
    *   Проводится анализ порога классификации для максимизации F1-score на тестовой выборке.
    *   Лучшая модель (состояние, конфигурация, оптимальный порог), векторизатор и параметры сохраняются в `model/torch_text/`.

#### 3.2.2. Классификатор изображений на основе ResNet (`resnet_learn_slut_detector.py`)

Скрипт для обучения модели классификации изображений на предмет содержания NSFW-контента.
*   **Модель ResNet34:**
    *   Используется предобученная на ImageNet модель ResNet34.
    *   "Голова" модели (полносвязный слой) заменяется на кастомную, состоящую из нескольких слоев `Linear`, `BatchNorm1d`, `ReLU`, `Dropout` и финального `Sigmoid`.
    *   Применяется прогрессивная разморозка слоев в процессе обучения.
*   **Данные и аугментация:**
    *   Изображения загружаются из директорий `data/raw/slut` и `data/raw/regular`.
    *   Применяется обширная аугментация для обучающей выборки (повороты, отражения, изменение цвета, аффинные преобразования, перспектива).
*   **Обучение:**
    *   `WeightedRandomSampler` используется для балансировки классов.
    *   Потенциально используется взвешенная функция потерь (`pos_weight` в `BCEWithLogitsLoss`, хотя с `Sigmoid` на выходе корректнее `BCELoss`).
    *   Оптимизатор `AdamW`, планировщик `ReduceLROnPlateau`.
    *   Применяется обучение со смешанной точностью (`GradScaler`, `autocast`).
    *   Реализована ранняя остановка.
*   **Оценка и метрики:**
    *   Модель оценивается по Accuracy, ROC-AUC, Average Precision, F1-score, Precision, Recall.
    *   Сохраняются Confusion Matrix, ROC-кривая, Precision-Recall кривая, история обучения. Порог классификации (0.5 для ResNet, согласно README) используется для бинарных метрик.
*   **Экспорт:** Модель экспортируется в ONNX и проходит динамическую квантизацию.

### 3.3. Сервер API (`main.py`)

Сервер API на FastAPI предоставляет интерфейс к обученным моделям.
*   **Инициализация:** При старте загружаются:
    *   **Текстовый классификатор:** Модель PyTorch MLP и TF-IDF векторизатор из `model/torch_text/`.
    *   **Классификатор изображений:** Модель ResNet34 из `model/resnet/`.
*   **Эндпоинты:**
    *   `POST /api/classify_text/`: Принимает текст, возвращает вероятность рекламы, флаг `is_ad` и уверенность.
    *   `POST /api/classify_image/`: Принимает файл изображения, возвращает вероятность NSFW, флаг `is_nsfw` и уверенность.
    *   `GET /health`: Статус работоспособности сервера и моделей.
*   **Middleware:** Логирование запросов, проверка размера файла (лимит 25MB для изображений), CORS.
*   **Безопасность:** Предполагается использование HTTPS, например, через Cloudflare, как указано в README.

#### 3.3.1. Архитектура текстового классификатора (`model_architecture.py`)

Определяет класс `AdvancedTextClassifier` (MLP), используемый в `torch_text.py` и загружаемый `main.py`. Гибкая структура с настраиваемыми слоями, активациями, Dropout и BatchNorm.

#### 3.3.2. Реализация API

`main.py` использует FastAPI для создания RESTful API, Pydantic для валидации данных. Классы `TextClassifier` и `ImageClassifier` инкапсулируют логику загрузки моделей и выполнения предсказаний.

*   Определение всплывающего окна (`popup.html`).

#### 3.4.2. Пользовательский интерфейс (`popup.html`, `popup.css`)

*   `popup.html`: HTML-структура всплывающего окна с настройками (режим отображения, порог, управление списком каналов, импорт/экспорт).
*   `popup.css`: CSS-стили для оформления интерфейса в темной теме с использованием современных техник (CSS переменные, `backdrop-filter`, анимации).

#### 3.4.3. Логика всплывающего окна (`popup.js`)

Управляет интерактивностью всплывающего окна:
*   Загружает и сохраняет настройки (режим отображения, порог, список каналов) в `chrome.storage.local`.
*   Отображает и позволяет редактировать список исключенных каналов.
*   Реализует функции импорта и экспорта списка каналов в формате JSON.

#### 3.4.4. Фоновый скрипт (`background.js`)

Выполняет задачи в фоновом режиме:
*   Принимает сообщения от других частей расширения (например, от `content.js`) с действием `classify`.
*   Отправляет текст сообщения на сервер API (`https://blackfoxus.ru:8000/api/classify_text`) для классификации.
*   Возвращает результат классификации обратно инициатору запроса.
*   **Примечание:** Текущая реализация `background.js` обрабатывает только классификацию текста. Для классификации изображений потребуется аналогичная логика с обращением к `/api/classify_image/`.

#### 3.4.5. Скрипт взаимодействия со страницей (`content.js` - предполагаемый)

Хотя файл `content.js` не предоставлен, его роль в подобном расширении заключается в следующем:
*   **Обнаружение сообщений:** Мониторинг DOM-структуры Telegram Web (например, с помощью `MutationObserver`) для обнаружения новых и существующих сообщений.
*   **Сбор контента:** Извлечение текста сообщений и, возможно, URL изображений.
*   **Отправка на классификацию:** Передача собранного контента в `background.js` для отправки на сервер.
*   **Применение фильтрации:** На основе ответа от `background.js` (результата классификации) и настроек пользователя (режим отображения, порог), `content.js` будет модифицировать DOM:
    *   Добавлять CSS-классы для подсветки.
    *   Скрывать элементы.
    *   Изменять прозрачность.
    *   Отображать вероятность рядом с сообщением.
*   **Кнопка/интеграция в UI:** Возможно, добавление элементов управления или индикаторов непосредственно на страницу Telegram Web.

## 4. Используемые технологии

### 4.1. Python и его экосистема
Основной язык для бэкенда и обучения моделей.

### 4.2. FastAPI
Современный веб-фреймворк для создания API.

### 4.3. PyTorch и TorchVision
Библиотека для глубокого обучения и пакет для задач компьютерного зрения.

### 4.4. ResNet (Residual Networks)
Архитектура сверточной нейронной сети, используемая для классификации изображений. Ключевая особенность – остаточные блоки с skip-соединениями, позволяющие обучать очень глубокие сети.

### 4.5. TF-IDF (Term Frequency-Inverse Document Frequency)
Метод векторизации текста, оценивающий важность слова в документе относительно корпуса.

### 4.6. TDLib (Telegram Database Library)
Кроссплатформенная библиотека для создания кастомных клиентов Telegram, используемая в `listener.py`.

### 4.7. Optuna
Фреймворк для автоматической оптимизации гиперпараметров. В проекте используется TPE (Tree-structured Parzen Estimator) – байесовский подход, строящий вероятностные модели для "хороших" и "плохих" параметров и выбирающий новые точки для проверки, максимизируя ожидаемое улучшение.

### 4.8. Технологии веб-расширения
HTML, CSS, JavaScript и Chrome Extension APIs (`storage`, `runtime messaging`).

### 4.9. Методы балансировки данных (обзор)
Проблема несбалансированных классов часто встречается в задачах классификации. Существуют различные подходы к ее решению:
*   **Oversampling (Увеличение выборки меньшего класса):**
    *   `RandomOverSampler`: Случайное дублирование примеров меньшего класса.
    *   `SMOTE` (Synthetic Minority Over-sampling Technique): Создает синтетические примеры меньшего класса, интерполируя между существующими примерами и их ближайшими соседями.
    *   `ADASYN`: Адаптивный вариант SMOTE, генерирующий больше синтетических данных для примеров, которые сложнее классифицировать.
*   **Undersampling (Уменьшение выборки большего класса):**
    *   `RandomUnderSampler`: Случайное удаление примеров из большего класса.
    *   `Tomek Links`: Находит пары ближайших соседей из разных классов. Если такая пара является Tomek Link (между ними нет других точек их же классов), пример из большего класса удаляется. Это помогает очистить границу между классами.
*   **Combined (Комбинированные методы):**
    *   Сочетают oversampling и undersampling. Например, `SMOTE + Tomek Links`: сначала SMOTE увеличивает меньший класс, затем Tomek Links удаляют потенциальный шум или неоднозначные примеры на границе классов.
*   **Weighted Classes (Взвешивание классов):**
    *   Модификация функции потерь модели таким образом, чтобы ошибки на примерах меньшего класса имели больший вес. Многие классификаторы (включая RandomForest, LogisticRegression, и некоторые нейросетевые функции потерь в PyTorch) поддерживают параметр `class_weight`.
В данном проекте для текстовой модели (`torch_text.py`) используется `WeightedRandomSampler` в `DataLoader` и потенциально взвешивание в `CrossEntropyLoss`, что является формой взвешивания классов. Для модели изображений (`resnet_learn_slut_detector.py`) также применяется `WeightedRandomSampler` и может использоваться `pos_weight` в функции потерь. README упоминает, что для проекта был выбран "combined" метод, так как другие не давали прироста качества, что может указывать на эксперименты с `SMOTE + Tomek Links` на ранних этапах или для других, не вошедших в финальную версию, моделей.

## 6. Результаты и обсуждение

### 6.1. Качество моделей

#### 6.1.1. Модель классификации изображений (ResNet)
Согласно `README.md`, модель ResNet для классификации NSFW-изображений показывает высокую точность.
*   **F1-score = 0.98**
*   **Accuracy = 0.99**
*   **ROC-AUC = 0.999**
*   Ложные срабатывания составляют менее 1%.
Такие высокие показатели свидетельствуют о надежности модели. Однако, как отмечено в `README.md`, столь высокие значения на тестовых данных могут указывать на недостаточное разнообразие тестовой выборки или ее схожесть с обучающей. В реальных условиях производительность может несколько отличаться. Оптимальный порог для ResNet модели, согласно README, составляет 0.5.

#### 6.1.2. Модель классификации текста (PyTorch MLP)
Для текстовой модели, обученной в `torch_text.py`, важным этапом является настройка порога классификации. На представленном в `README.md` графике зависимости Precision, Recall и F1-score от порога, оптимальный порог (например, 0.43, как указано в тексте README для текстовой модели) выбирается для максимизации F1-score. Конкретные значения метрик для текстовой модели на тестовой выборке зависят от результатов обучения и выбранного порога.

### 6.2. Ограничения и возможные проблемы
*   **Качество и объем данных:** Точность моделей критически зависит от обучающих данных.
*   **Эволюция контента:** Модели требуют регулярного дообучения.
*   **Производительность:** Классификация изображений может быть ресурсоемкой.
*   **Ограничения Telegram API:** Лимиты на запросы могут влиять на сбор данных.
*   **Ложные срабатывания:** Неизбежны для ML-моделей; важен правильный подбор порога.
*   **Зависимость от верстки Telegram Web:** Изменения в DOM могут сломать расширение.

### 6.3. Направления для дальнейшего развития
*   **Улучшение моделей:** Использование трансформеров для текста, эксперименты с другими архитектурами для изображений, активное обучение.
