## 1. Введение

### 1.1. Актуальность проблемы

Мессенджер Telegram завоевал огромную популярность как средство быстрой и безопасной коммуникации, а также как платформа для распространения информации через каналы и группы. Однако, наряду с ценным контентом, пользователи все чаще сталкиваются с агрессивной рекламой и нежелательными материалами, включая контент для взрослых (NSFW) в сообщениях и на аватарках пользователей. Такой "визуальный шум" не только отвлекает, но и может создавать дискомфорт, особенно в публичных пространствах. Ручная фильтрация неэффективна и трудоемка. В связи с этим, разработка интеллектуальных инструментов для автоматической классификации и фильтрации контента является актуальной задачей, направленной на улучшение пользовательского опыта.

### 1.2. Цель и задачи проекта

**Цель проекта:** Создать инструмент для автоматической фильтрации текстовой рекламы и обнаружения NSFW-контента (в текстовых сообщениях и на изображениях, включая аватарки пользователей) в Telegram, который повысит удобство использования мессенджера, уберёт визуальный шум и повысит безопасность пользователей.

**Задачи проекта:**

1.  Разработать методы сбора и подготовки данных из Telegram и других источников (например, Reddit).
2.  Подготовить и разметить наборы данных для обучения моделей машинного обучения, включая удаление дубликатов изображений.
3.  Разработать и обучить модель на основе нейронной сети PyTorch для классификации текстовых сообщений (реклама/не реклама).
4.  Разработать и обучить модель на основе архитектуры ResNet для классификации изображений (NSFW/SFW), включая аватарки.
5.  Реализовать серверное API на FastAPI для предоставления доступа к обученным моделям.
6.  Создать расширение для браузера Chrome, использующее API для фильтрации контента в веб-версии Telegram.
7.  Обеспечить возможность развертывания и эксплуатации ключевых компонентов системы.

### 1.3. Обзор решения

Предлагаемая система представляет собой многокомпонентное решение:
*   **Подсистема сбора данных:** Включает модуль `listener.py` для автоматизированного сбора сообщений через TDLib, использование стандартных функций экспорта Telegram для получения текстовых данных в формате JSON, скрипт `reddit_data.py` для сбора изображений с Reddit, и скрипт `dubl_check.py` для удаления дубликатов изображений. Скрипт `merge.py` используется для предобработки и объединения JSON-дампов текстовых сообщений.
*   **Подсистема обучения моделей:**
    *   `torch_text.py`: Отвечает за обучение нейросетевой модели (MLP) на PyTorch для классификации текста, используя TF-IDF векторизацию и оптимизацию гиперпараметров с Optuna.
    *   `resnet_learn_slut_detector.py`: Используется для обучения модели ResNet34 для классификации изображений (включая аватарки) на NSFW/SFW контент, с применением техник аугментации и балансировки классов.
*   **Сервер API (`main.py`):** Реализован на FastAPI, предоставляет HTTP-эндпоинты для классификации текста и изображений (включая аватарки), используя обученные модели.
*   **Клиентское приложение (Расширение для браузера Chrome):** Интегрируется с веб-версией Telegram, отправляет контент (текст сообщений, данные аватарок) на сервер API для анализа и применяет выбранный пользователем способ фильтрации.

### 1.4. Ценность для пользователя

Рекламные сообщения, спам и нежелательный контент являются распространенными раздражителями в интернете, снижающими комфорт использования платформ. Пользователи стремятся избавиться от этого "визуального шума" и оградить себя от потенциально неприемлемых материалов. Данный проект предлагает решение, которое:
*   **Уменьшает количество навязчивой рекламы:** Освобождает ленту от избыточных коммерческих предложений.
*   **Фильтрует NSFW-контент:** Повышает безопасность и комфорт при использовании Telegram, особенно в публичных чатах, каналах и при просмотре аватарок пользователей, предотвращая случайный просмотр неподходящих материалов. Позволяет настроить отображение NSFW аватарок (размытие, скрытие, рамка).
*   **Повышает удобство использования:** Делает взаимодействие с мессенджером более целенаправленным и приятным.

## 2. Архитектура системы

### 2.1. Общая архитектура

Архитектура проекта является многоуровневой и модульной, что обеспечивает гибкость разработки и развертывания (см. Приложение А: UML-диаграммы системы).

1.  **Уровень сбора и подготовки данных:**
    *   Используется встроенная функция экспорта чатов из Telegram Desktop для получения истории текстовых сообщений в формате JSON.
    *   Скрипт `merge.py` обрабатывает и объединяет эти JSON-файлы.
    *   Скрипт `listener.py` (использующий TDLib) служит для потенциального автоматизированного сбора больших объемов текстовых данных.
    *   Скрипт `reddit_data.py` используется для сбора изображений с платформы Reddit (SFW и NSFW) с помощью PRAW.
    *   Скрипт `dubl_check.py` применяется для поиска и удаления дубликатов в собранных наборах изображений на основе их хешей.
2.  **Уровень обучения моделей (локальная среда разработчика):**
    *   Скрипты `torch_text.py` и `resnet_learn_slut_detector.py` используют подготовленные датасеты (текстовые из `data/reklama`, `data/nereklama`; изображения из `data/raw/slut`, `data/raw/regular`) для обучения моделей.
    *   Артефакты обучения (веса моделей, конфигурации, векторизаторы) сохраняются в директорию `model`.
3.  **Уровень предоставления сервиса (API-сервер):**
    *   `main.py`, реализованный на FastAPI, разворачивается на удаленном сервере.
    *   API-сервер загружает обученные модели из директории `model` и предоставляет HTTP-эндпоинты для классификации текста и изображений.
4.  **Уровень клиента (браузерное расширение):**
    *   Расширение для Chrome взаимодействует с API-сервером, отправляя данные (текст сообщений, данные аватарок в виде URL или ArrayBuffer) для анализа.
    *   На основе полученных от сервера классификаций, расширение модифицирует отображение контента в веб-интерфейсе Telegram.

### 2.2. Взаимодействие компонентов

*   Текстовые данные, экспортированные из Telegram Desktop, обрабатываются `merge.py`. Дополнительные текстовые данные могут собираться `listener.py`.
*   Изображения для обучения собираются с Reddit скриптом `reddit_data.py` и сохраняются в соответствующие директории (`data/reddit/sfw_images`, `data/reddit/nsfw_images`), которые затем могут быть перемещены или скопированы в `data/raw`. После этого `dubl_check.py` используется для очистки `data/raw` от дубликатов.
*   Скрипты обучения (`torch_text.py`, `resnet_learn_slut_detector.py`) используют эти подготовленные данные для тренировки моделей локально.
*   Сервер API (`main.py`) загружает обученные модели и ожидает запросы.
*   Расширение для Chrome (`background.js`) отправляет текстовые данные и данные изображений аватарок (URL или ArrayBuffer) на соответствующие эндпоинты API-сервера.
*   `content.js` (часть расширения) обнаруживает текстовые сообщения и аватарки, отправляет их на анализ через `background.js` и применяет изменения к DOM веб-страницы Telegram на основе ответов сервера и настроек пользователя.
*   `popup.js` позволяет пользователю настраивать параметры фильтрации текстовой рекламы и отображения NSFW-аватарок, а также управлять списком исключенных каналов.

## 3. Описание компонентов системы

### 3.1. Сбор и подготовка данных

Качество и объем данных являются критически важными для обучения эффективных моделей машинного обучения. В проекте используются различные источники и инструменты для сбора и подготовки как текстовых, так и графических данных.

#### 3.1.1. Модуль сбора данных (`listener.py`)

Скрипт `listener.py` предназначен для автоматизированного сбора текстовых сообщений из Telegram и их первичной классификации/сохранения. В текущем рабочем процессе проекта он в большей степени служит как инструмент для накопления данных, которые могут быть использованы для дальнейшего дообучения моделей.
*   **Интеграция с TDLib:** Использует `TDLib` для взаимодействия с Telegram API.
*   **Авторизация:** Поддерживает полный процесс авторизации.
*   **Сбор сообщений:** Может получать историю чатов и новые сообщения.
*   **Дедупликация:** Применяет `ScalableBloomFilter` для избежания дублирования сообщений.
*   **Потенциальная классификация и сохранение:** В коде предусмотрена отправка сообщений на внешний API для классификации и проверка на рекламу по ключевым словам. Сообщения сохраняются в CSV-файлы (`advertisements.csv`, `regular_messages.csv`) батчами, с указанием текста, хеша, результата классификации (если получен), ID отправителя, информации о чате и даты.

#### 3.1.2. Модуль слияния данных (`merge.py`)

Этот скрипт используется для обработки JSON-файлов, полученных путем экспорта данных из Telegram.
*   **Обработка JSON:** Читает файлы `result.json` из директорий с рекламными и нерекламными данными.
*   **Извлечение и дедупликация текста:** Аккуратно извлекает текстовое содержимое сообщений и удаляет дубликаты, чтобы обеспечить уникальность постов в обучающих выборках.
*   **Сохранение:** Формирует и сохраняет очищенные данные в файлы `reklama_data.json` и `nereklama_data.json`.

#### 3.1.3. Экспорт данных из Telegram Desktop

Основным методом сбора текстовых данных для обучения моделей в текущей итерации проекта является использование встроенной функции экспорта чатов в клиенте Telegram Desktop. Продолжительное время собирались рекламные и не рекламные посты в двух отдельных каналах в телеграмм. Также этот метод использовался для сбора датасета для классификации аватарок на nsfw и sfw, но к удивлению, в телеграмм не так много nsfw фотографий, поэтому пришлось подключать другие источники.

#### 3.1.4. Сбор изображений с Reddit (`reddit_data.py`)

Для обучения модели классификации изображений (NSFW/SFW) необходим большой и разнообразный датасет. Скрипт `reddit_data.py` автоматизирует процесс сбора изображений с платформы Reddit.
*   **Использование PRAW:** Взаимодействует с Reddit API через библиотеку PRAW (Python Reddit API Wrapper).
*   **Конфигурация:** Загружает учетные данные API из `.env` файла. 
*   **Загрузка изображений:** Итерируется по указанным сабреддитам, загружая изображения из постов. Обрабатывает как прямые ссылки на изображения, так и галереи.
*   **Сохранение:** Сохраняет загруженные изображения в структурированные директории (`data/reddit/sfw_images/<subreddit_name>` и `data/reddit/nsfw_images/<subreddit_name>`).
*   **Обработка ошибок и ограничений:** Включает таймауты, обработку ошибок сети, проверку Content-Type, ограничение на количество загрузок с одного сабреддита и санитайзер имен файлов.

#### 3.1.5. Удаление дубликатов изображений (`dubl_check.py`)

После сбора большого количества изображений из различных источников, включая Reddit, вероятно наличие дубликатов. Скрипт `dubl_check.py` предназначен для их обнаружения и удаления.
*   **Хеширование файлов:** Вычисляет хеш (MD5 или SHA256) для каждого файла изображения в указанной директории и ее поддиректориях. SHA256 более надежен, но медленнее.
*   **Проверка на изображение:** Перед хешированием проверяет, является ли файл действительным изображением, пытаясь его открыть с помощью Pillow.
*   **Обнаружение дубликатов:** Сравнивает хеши файлов. Файлы с одинаковыми хешами считаются дубликатами.
*   **Стратегии удаления:**
    *   `first_found`: Оставляет первый найденный файл (порядок зависит от `os.walk`).
    *   `shortest_path`: Оставляет файл с самым коротким путем (часто это файл с оригинальным именем, а не копия в глубокой поддиректории).
*   **Интерактивное удаление:** Запрашивает подтверждение у пользователя перед фактическим удалением файлов.
*   **Отчетность:** Предоставляет статистику по количеству отсканированных файлов, найденных и удаленных дубликатов.

### 3.2. Обучение моделей машинного обучения

#### 3.2.1. Классификатор текста на основе PyTorch (`torch_text.py`)

Этот скрипт реализует полный конвейер для обучения модели классификации текстов (реклама/не реклама).
*   **Данные и предобработка:**
    *   Загружает данные из JSON-файлов.
    *   Тексты очищаются, данные делятся на обучающую, валидационную и тестовую выборки.
*   **Векторизация TF-IDF:**
    *   `TfidfVectorizer` из `scikit-learn` преобразует тексты в числовые векторы.
    * Важность слова в документе (TF – частота термина), Редкость слова во всём корпусе (IDF – обратная частота документа).
    * Каждому слову (или N-грамме) присваивается вес на основе TF-IDF.
    * Текст превращается в разреженную матрицу (например, в формате SciPy CSR), где строки – документы, а столбцы – признаки (слова/N-граммы).
    * Использование русских стоп-слов , stop_words=russian – автоматически исключает частые, но малозначимые слова (например, «и», «в», «на»). Это уменьшает размерность данных и ускоряет обработку.
    * N-граммы (1,2) ngram_range=(1, 2) – учитывает не только отдельные слова (униграммы), но и пары подряд идущих слов (биграммы).
        * Пример: Униграммы: ["привет", "мир"] Биграммы: ["привет мир"]. Помогает улавливать контекст (например, «очень плохо» ≠ «плохо»).
    * Настройки min_df и max_df.
        * min_df (например, min_df=2) – игнорирует слова, встречающиеся реже чем в N документах. Убирает редкие термины (возможно, опечатки или шум).
        * max_df (например, max_df=0.8) – игнорирует слова, встречающиеся в >80% документов (слишком частые = мало информации).

*   **Модель (`AdvancedTextClassifier`):**
    *   Применяется многослойный перцептрон (MLP), определенный в `model_architecture.py` (и внутри самого `torch_text.py`). Архитектура включает настраиваемое число слоев, нейронов, функции активации, Dropout и Batch Normalization.
*   **Оптимизация гиперпараметров с Optuna:**
    *   Optuna используется для автоматического подбора оптимальной конфигурации MLP (архитектура, learning rate, batch size, dropout и т.д.) с целью максимизации F1-score на валидационной выборке.
*   **Обучение:**
    *   Применяется `WeightedRandomSampler` для балансировки классов в `DataLoader`.
    *   Используется `CrossEntropyLoss` и оптимизаторы (AdamW или RMSprop), подобранные Optuna.
    *   Реализован механизм ранней остановки.
*   **Оценка и сохранение:**
    *   Финальная модель обучается на объединенных данных (train+validation) с лучшими гиперпараметрами.
    *   Проводится анализ порога классификации для максимизации F1-score на тестовой выборке.
    *   Лучшая модель (состояние, конфигурация, оптимальный порог), векторизатор и параметры сохраняются в `model/torch_text/`.

**1. Что такое "нейрон" (кружочек на схеме)?**

Каждый кружочек (кроме тех, что в самом первом, "Входном слое") представляет собой **искусственный нейрон** (или просто "нейрон", "узел"). Внутри каждого такого нейрона происходят две основные математические операции:

*   **a) Взвешенная сумма входов (Weighted Sum):**
    *   Каждый нейрон получает сигналы (числовые значения) от всех нейронов предыдущего слоя, с которыми он соединен линиями.
    *   Каждая такая линия (связь) имеет свой "вес" (weight). Вес — это число, которое показывает, насколько важен сигнал от конкретного нейрона предыдущего слоя для текущего нейрона. Сигнал умножается на этот вес.
    *   Нейрон суммирует все эти "взвешенные" входящие сигналы.
    *   К этой сумме также добавляется специальное число, называемое "смещением" (bias). Смещение позволяет нейрону быть активным, даже если все входящие сигналы малы, или наоборот, требовать более сильного суммарного сигнала для активации.
    *   **Формула (упрощенно):** `Выход_до_активации = (вход1 * вес1) + (вход2 * вес2) + ... + (входN * весN) + смещение`

*   **b) Функция активации (Activation Function):**
    *   Результат взвешенной суммы затем пропускается через **функцию активации**.
    *   Эта функция решает, должен ли нейрон "сработать" (активироваться) и какой силы сигнал он передаст дальше.
    *   Функции активации вносят нелинейность в модель, что позволяет нейросетям изучать сложные зависимости в данных. Без них вся сеть свелась бы к одной большой линейной операции.
    *   **Популярные функции активации:**
        *   **ReLU (Rectified Linear Unit):** Если вход больше нуля, выход равен входу. Если вход меньше или равен нулю, выход равен нулю. ( `max(0, x)` ) — очень распространена.
        *   **Sigmoid:** Преобразует любое число в значение от 0 до 1. Часто используется в выходном слое для задач бинарной классификации (чтобы получить вероятность).
        *   **Tanh (гиперболический тангенс):** Преобразует любое число в значение от -1 до 1.
    *   Выход функции активации – это и есть итоговый выходной сигнал нейрона, который передается всем соединенным с ним нейронам следующего слоя.

**2. Как информация проходит через сеть (на примере вашей схемы: 16 -> 12 -> 10 -> 1):**

*   **Входной слой (Input Layer ∈ ℝ¹⁶):**
    *   Это 16 нейронов, которые просто принимают исходные данные. Если бы это была задача классификации изображений, это могли бы быть значения пикселей. В вашем контексте (текстовая классификация), это, скорее всего, числовые представления слов или фраз (например, TF-IDF векторы или эмбеддинги слов). Для этой визуализации это просто 16 абстрактных входных чисел.
    *   Эти нейроны сами не выполняют вычислений взвешенной суммы или активации в том же смысле, что и скрытые/выходные. Они просто передают свои значения дальше.

*   **Первый скрытый слой (Hidden Layer ∈ ℝ¹²):**
    *   Каждый из 12 нейронов в этом слое соединен со *всеми* 16 нейронами входного слоя.
    *   Каждый из 12 нейронов независимо выполняет операции, описанные в пункте 1 (взвешенная сумма всех 16 входов + смещение, затем функция активации).
    *   Таким образом, этот слой преобразует исходные 16 признаков в 12 новых, более абстрактных признаков. Эти новые признаки являются комбинациями исходных, и сеть "учится" создавать такие комбинации, которые полезны для решения задачи.

*   **Второй скрытый слой (Hidden Layer ∈ ℝ¹⁰):**
    *   Каждый из 10 нейронов в этом слое соединен со *всеми* 12 нейронами предыдущего скрытого слоя.
    *   Снова, каждый из 10 нейронов выполняет взвешенную сумму своих 12 входов + смещение, и пропускает результат через функцию активации.
    *   Этот слой создает еще более сложные и абстрактные представления, основываясь на признаках, вычисленных первым скрытым слоем.

*   **Выходной слой (Output Layer ∈ ℝ¹):**
    *   Здесь у нас 1 нейрон. Он соединен со *всеми* 10 нейронами второго скрытого слоя.
    *   Он также выполняет взвешенную сумму своих 10 входов + смещение, и затем, как правило, применяет специфическую функцию активации, зависящую от задачи:
        *   **Для бинарной классификации (ответ "да/нет", "класс А/класс Б"):** Часто используется **Sigmoid**. Выход будет числом от 0 до 1, интерпретируемое как вероятность принадлежности к одному из классов (например, вероятность того, что текст позитивный).
        *   **Для регрессии (предсказание числового значения, например, цены):** Может использоваться **линейная функция активации** (т.е. фактически нет нелинейной активации, выход = взвешенная сумма) или вообще не быть функции активации. Выход будет предсказанным числом.
        *   **Для многоклассовой классификации:** Используется **Softmax** (если бы было несколько выходных нейронов, по одному на класс).

**3. Как нейросеть выдает "ответ":**

*   Значение (или значения), которое получается на выходе нейрона(ов) выходного слоя, и есть **"ответ" или "предсказание"** нейросети.
*   В вашем случае (1 выходной нейрон):
    *   Если это задача бинарной классификации и используется Sigmoid, то выход, например, 0.8, может означать 80% уверенности, что объект принадлежит к классу "1". Вы затем можете применить порог (например, 0.5): если выход > 0.5, то предсказываем класс "1", иначе класс "0".
    *   Если это задача регрессии, то выходное число (например, 25.3) и будет предсказанным значением.

**Самое главное: Обучение**

Веса и смещения в нейронах не задаются случайно (хотя инициализируются часто случайным образом). Они **подбираются в процессе обучения** нейросети.

1.  Сети показывают множество примеров данных (входы) вместе с правильными ответами (ожидаемые выходы).
2.  Сеть делает предсказание.
3.  Сравнивается предсказание сети с правильным ответом (вычисляется "ошибка" или "потери" – loss function).
4.  С помощью алгоритма **обратного распространения ошибки (backpropagation)** и методов оптимизации (например, градиентный спуск) веса и смещения во всей сети понемногу корректируются таким образом, чтобы уменьшить эту ошибку.
5.  Этот процесс повторяется много раз на большом наборе данных.

В результате обучения нейросеть "настраивает" свои внутренние параметры (веса и смещения) так, чтобы преобразовывать входные данные в правильные выходные ответы для конкретной задачи. Каждый нейрон в скрытых слоях учится распознавать определенные паттерны или комбинации признаков из предыдущего слоя, которые полезны для итогового предсказания.

        *   Помечает обработанные аватарки классом `nsfw-avatar-processed`.
*   **Кнопка исключения канала:** Добавляет кнопку "Фильтровать/Не фильтровать рекламу" в заголовок чата, состояние которой синхронизируется с `chrome.storage`.
*   **Управление состоянием:** Отслеживает изменения в `chrome.storage` для обновления настроек "на лету" и соответствующего переприменения стилей или перезапуска обработки.

## 4. Используемые технологии

### 4.1. Python и его экосистема
Основной язык для бэкенда и обучения моделей.

### 4.2. FastAPI
Современный веб-фреймворк для создания API.

### 4.3. PyTorch и TorchVision
Библиотека для глубокого обучения и пакет для задач компьютерного зрения.

### 4.4. ResNet (Residual Networks)
Архитектура сверточной нейронной сети, используемая для классификации изображений. Ключевая особенность – остаточные блоки с skip-соединениями, позволяющие обучать очень глубокие сети.

### 4.5. TF-IDF (Term Frequency-Inverse Document Frequency)
Метод векторизации текста, оценивающий важность слова в документе относительно корпуса.

### 4.6. TDLib (Telegram Database Library)
Кроссплатформенная библиотека для создания кастомных клиентов Telegram, используемая в `listener.py`.

### 4.7. PRAW (Python Reddit API Wrapper)
Библиотека для удобного взаимодействия с Reddit API, используемая в `reddit_data.py` для сбора изображений.

### 4.8. Optuna
Фреймворк для автоматической оптимизации гиперпараметров. В проекте используется TPE (Tree-structured Parzen Estimator) – байесовский подход, строящий вероятностные модели для "хороших" и "плохих" параметров и выбирающий новые точки для проверки, максимизируя ожидаемое улучшение.

### 4.9. Технологии веб-расширения
HTML, CSS, JavaScript и Chrome Extension APIs (`storage`, `runtime messaging`, `host_permissions`).

### 4.10. Методы балансировки данных (обзор)
Проблема несбалансированных классов часто встречается в задачах классификации. Существуют различные подходы к ее решению:
*   **Oversampling (Увеличение выборки меньшего класса):**
    *   `RandomOverSampler`: Случайное дублирование примеров меньшего класса.
    *   `SMOTE` (Synthetic Minority Over-sampling Technique): Создает синтетические примеры меньшего класса, интерполируя между существующими примерами и их ближайшими соседями.
    *   `ADASYN`: Адаптивный вариант SMOTE, генерирующий больше синтетических данных для примеров, которые сложнее классифицировать.
*   **Undersampling (Уменьшение выборки большего класса):**
    *   `RandomUnderSampler`: Случайное удаление примеров из большего класса.
    *   `Tomek Links`: Находит пары ближайших соседей из разных классов. Если такая пара является Tomek Link (между ними нет других точек их же классов), пример из большего класса удаляется. Это помогает очистить границу между классами.
*   **Combined (Комбинированные методы):**
    *   Сочетают oversampling и undersampling. Например, `SMOTE + Tomek Links`: сначала SMOTE увеличивает меньший класс, затем Tomek Links удаляют потенциальный шум или неоднозначные примеры на границе классов.
*   **Weighted Classes (Взвешивание классов):**
    *   Модификация функции потерь модели таким образом, чтобы ошибки на примерах меньшего класса имели больший вес. Многие классификаторы (включая RandomForest, LogisticRegression, и некоторые нейросетевые функции потерь в PyTorch) поддерживают параметр `class_weight`.
В данном проекте для текстовой модели (`torch_text.py`) используется `WeightedRandomSampler` в `DataLoader` и потенциально взвешивание в `CrossEntropyLoss`, что является формой взвешивания классов. Для модели изображений (`resnet_learn_slut_detector.py`) также применяется `WeightedRandomSampler` и может использоваться `pos_weight` в функции потерь.

## 6. Результаты и обсуждение

### 6.1. Качество моделей

#### 6.1.1. Модель классификации изображений (ResNet)
Модель ResNet используется для классификации NSFW-изображений, включая аватарки пользователей. Согласно результатам скрипта обучения `resnet_learn_slut_detector.py`, модель показывает высокую точность:
*   **F1-score = 0.98**
*   **Accuracy = 0.99**
*   **ROC-AUC = 0.999**
*   Ложные срабатывания составляют менее 1%.
Такие высокие показатели свидетельствуют о надежности модели для определения NSFW-контента. Однако столь высокие значения на тестовых данных могут указывать на недостаточное разнообразие тестовой выборки или ее схожесть с обучающей. В реальных условиях на разнообразных аватарках производительность может несколько отличаться. Оптимальный порог для ResNet модели по умолчанию составляет 0.5.

#### 6.1.2. Модель классификации текста (PyTorch MLP)
Для текстовой модели, обученной в `torch_text.py`, важным этапом является настройка порога классификации. Оптимальный порог (0.43) выбирается для максимизации F1-score на валидационной/тестовой выборке. Конкретные значения метрик для текстовой модели на тестовой выборке зависят от результатов обучения и выбранного порога.

### 6.2. Ограничения и возможные проблемы
*   **Качество и объем данных:** Точность моделей (как текстовой, так и для изображений) критически зависит от обучающих данных. Для аватарок важно иметь разнообразный датасет, отражающий различные стили и типы изображений. Сбор качественных и разнообразных данных является постоянной задачей.
*   **Эволюция контента:** Модели требуют регулярного дообучения на новых данных, так как способы подачи рекламы и типы NSFW-контента могут меняться.
*   **Производительность:** Классификация изображений очень ресурсоемка для API. Кэширование на стороне клиента (`content.js`) помогает снизить нагрузку, но первоначальная классификация все равно требует вычислительных ресурсов.
*   **Ложные срабатывания:** Неизбежны для ML-моделей; важен правильный подбор порога и возможность для пользователя настроить чувствительность, чтобы переложить часть ответственности на него).
*   **Зависимость от верстки Telegram Web:** Изменения в DOM веб-версии Telegram могут сломать работу расширения.

### 6.3. Направления для дальнейшего развития
*   **Улучшение моделей:** Использование трансформеров для текста, эксперименты с другими архитектурами для изображений (например, Vision Transformers), активное обучение для обеих задач.
*   **Расширение функционала:**
    *   Классификация изображений непосредственно в сообщениях (не только аватарок).
    *   Поддержка других типов контента (видео, GIF).
    *   Пользовательская разметка для дообучения моделей (механизм обратной связи от пользователя).
    *   Версии для других браузеров.
*   **Улучшение UX/UI:** Более гибкие настройки фильтрации, возможность быстро пометить ложное срабатывание.
*   **Мониторинг:** Отслеживание точности моделей в реальном времени и сбор статистики по ложным срабатываниям для улучшения датасетов.
*   **Оптимизация классификации аватарок:** Исследование возможности пакетной отправки аватарок на классификацию или более эффективных методов передачи данных.
*   **Улучшение процесса сбора данных:** Автоматизация запуска скриптов сбора и очистки данных, интеграция с системами версионирования данных.

## 7. Заключение

В рамках курсовой работы была разработана и описана комплексная система для автоматической классификации текстовой рекламы и NSFW-контента в Telegram. Система включает компоненты для сбора и подготовки данных (включая сбор с Reddit и удаление дубликатов изображений), обучения моделей глубокого обучения (MLP для текста и ResNet для изображений, включая аватарки), серверное API для предоставления сервиса классификации и клиентское расширение для браузера Chrome.

Проект успешно демонстрирует применение современных технологий машинного обучения и веб-разработки для решения актуальной задачи улучшения пользовательского опыта. Внедрение классификации аватарок дополнительно повышает комфорт и безопасность использования мессенджера. Достигнутые показатели качества моделей (особенно для изображений) являются высокими, хотя и требуют осторожной интерпретации в контексте разнообразия реальных данных и необходимости постоянного обновления моделей.

Разработанное решение является гибким и масштабируемым, с четко выделенными модулями и возможностями для дальнейшего совершенствования и расширения функциональности, включая более глубокую интеграцию анализа изображений и улучшение процессов управления данными.
