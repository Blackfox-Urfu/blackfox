# 5 пункт
### Основные термины

*  **Линейное программирование (ЛП)**: Математический метод оптимизации, используемый для нахождения наилучшего решения (например, максимальной прибыли или минимальных затрат) в математической модели, чьи требования представлены линейными отношениями.
*  **Целевая функция**: Функция, которую необходимо минимизировать или максимизировать в задаче линейного программирования. В данном случае целевой функцией является минимизация стоимости серверов.
*  **Ограничения**: Линейные равенства или неравенства, определяющие допустимые значения переменных. В данном случае ограничениями являются требуемое количество пользователей и максимальное энергопотребление.
*  **Переменные решения**: Переменные, значения которых необходимо определить в процессе решения задачи линейного программирования. В данном случае это количество серверов каждого типа.
* **Допустимая область**: Область в пространстве переменных решения, которая удовлетворяет всем ограничениям. Она всегда представляет собой выпуклый многогранник.
* **Оптимальное решение**: Точка в допустимой области, в которой целевая функция достигает своего экстремального значения.
* **CPU**: Центральный процессор.
* **FLOPS (Floating Point Operations Per Second)**: Количество операций с плавающей запятой в секунду, мера производительности процессора.
* **CAPEX (Capital Expenditures)**: Капитальные затраты.
* **Симплекс-метод**: Один из основных алгоритмов решения задач линейного программирования.
* **FLOPS** (Floating Point Operations Per Second) — это единица измерения производительности компьютера или процессора, которая показывает, сколько операций с плавающей запятой может быть выполнено за одну секунду.

### Общее описание
Задача заключается в оптимизации конфигурации серверного кластера путем выбора оптимального количества серверов разных типов. Цель - минимизировать общую стоимость при обеспечении требуемой производительности и соблюдении ограничений по энергопотреблению.

### Управляющие переменные
1. **$x$** - количество серверов первого типа (целое, неотрицательное)
2. **$y$** - количество серверов второго типа (целое, неотрицательное)

### Ресурсные ограничения и экономические показатели

1.  **Ресурсные ограничения:**
    *   **Производительность процессоров (`flops`)**:  Используется для *расчета* `power` (максимального количества пользователей на сервер).  Сам по себе `flops` напрямую в оптимизации не участвует.
    *   **Энергопотребление (`consumption`)**:  Используется в качестве *ограничения*. Суммарное энергопотребление всех серверов не должно превышать `max_consumption`.
    *   **Мощность (`power`)**:  Показывает, сколько пользователей может обслужить один сервер. *Ключевой параметр*, определяющий производительность сервера.

2.  **Ограничения по экономическим показателям:**
    *   **Стоимость серверов (`cost`)**:  Используется в *целевой функции*.  Суммарная стоимость серверов минимизируется.
    *   **Доход с одного пользователя**:  В текущей версии кода *не используется*.  Этот параметр был важен для расчета прибыли в предыдущей версии, но в текущей постановке задачи прибыль не максимизируется, а минимизируется стоимость при заданном количестве пользователей.
    * **Переменные затраты**: В данной версии кода *не учитываются*.

3.  **Основные экономические ограничения:**
    *   **Капитальные затраты (CAPEX)**:  Неявно ограничены бюджетом, который определяется количеством пользователей и стоимостью серверов.
    *   **Энергопотребление (`consumption`)**:  Ограничено параметром `max_consumption`

### Выбор целевой функции
Целевая функция минимизирует общую стоимость серверов:
$$
f(x,y) = c_1x + c_2y \rightarrow \min
$$
где:
- $c_1$ - стоимость сервера первого типа
- $c_2$ - стоимость сервера второго типа
- $x, y$ - количество серверов каждого типа

### Математическая модель
1. **Целевая функция**: 
   $$
   f(x,y) = c_1x + c_2y \rightarrow \min
   $$

2. **Ограничения**:
   - По производительности (обслуживание пользователей):
     $$
     p_1x + p_2y \geq users
     $$
   - По энергопотреблению:
     $$
     e_1x + e_2y \leq max\_consumption
     $$
   - Неотрицательность переменных:
     $$
     x \geq 0, \quad y \geq 0
     $$

где:
- $p_1, p_2$ - производительность (power) серверов каждого типа
- $e_1, e_2$ - энергопотребление (consumption) серверов каждого типа
- $users$ - требуемое количество пользователей
- $max\_consumption$ - максимальное допустимое энергопотребление

### Содержательно математический анализ
1. **Допустимая область** определяется пересечением:
   - Области выше прямой требуемой производительности
   - Области ниже прямой ограничения энергопотребления
   - Области где количество серверов неотрицательное ($x \geq 0$ и $y \geq 0$)  .

2. **Оптимальное решение**:
   - Находится на границе допустимой области
   - Определяется методом линейного программирования 

3. **Визуализация**:
   - Строится график с допустимой областью (зеленая заливка)
   - Отображаются ограничения (красная и синяя линии)
   - Отмечается оптимальное решение (красная точка)
   - Добавляются подписи и легенда для наглядности

## Оценка мощности сервера

$$
\text{FLOPS} = F \times O \times C
$$  
- **$F$** — тактовая частота процессора (Hz),
- **$O$** — количество операций с плавающей запятой за такт,
- **$C$** — количество ядер процессора.

#### 2. **Функция `linear_programming_example`**

```python
def linear_programming_example(users, CPU, max_consumption):
    """
    Решает задачу линейного программирования и строит график.
    """
    cpu_models = list(CPU.keys())
    costs = [CPU[cpu]['cost'] for cpu in CPU]
    powers = [CPU[cpu]['power'] for cpu in CPU]
    consumptions = [CPU[cpu]['consumption'] for cpu in CPU]
    
    c = costs
    A = [[-powers[0], -powers[1]],
         [consumptions[0], consumptions[1]]]
    b = [-users, max_consumption]
    bounds = [(0, None), (0, None)]
    
    result = linprog(c, A_ub=A, b_ub=b, bounds=bounds, method='highs')
    
    if result.success:
        # Округляем решения до целых чисел в большую сторону
        x_rounded = np.ceil(result.x[0])
        y_rounded = np.ceil(result.x[1])

        # ... (построение графика) ...
    else:
        print("Linear programming failed:", result.message)
```

Эта функция выполняет следующие действия:

1.  **Формирует задачу линейного программирования**:
    *   **Целевая функция (`c`)**: Минимизация стоимости серверов:  `c = costs`.  Значение `costs` содержит стоимости серверов с различными CPU.
    *   **Ограничения (`A`, `b`)**:
        *   Обслуживание заданного количества пользователей: `-powers[0] * x - powers[1] * y <= -users`.  Здесь `x` и `y` - количество серверов с первым и вторым типом CPU, соответственно. `powers` содержит данные о максимальном количестве пользователей на сервер.
        *   Ограничение на максимальное энергопотребление: `consumptions[0] * x + consumptions[1] * y <= max_consumption`.
    *   **Границы переменных (`bounds`)**:  Количество серверов не может быть отрицательным: `x >= 0`, `y >= 0`.
2.  **Решает задачу линейного программирования**:
	**linprog(c, A_ub=A, b_ub=b, bounds=bounds, method='highs')**

	- **[linprog](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.linprog.html)**: Это функция из модуля scipy.optimize, предназначенная для решения задач линейного программирования. Она находит значения переменных, минимизирующих целевую функцию при заданных ограничениях.
	    
	- **c**: Это вектор коэффициентов целевой функции. В данном коде c = costs, то есть целевая функция имеет вид:
	    
	    $$
	    c[0] * x[0] + c[1] * x[1] + ... + c[n-1] * x[n-1]
	    $$
	    где x[i] - переменные решения (в данном случае - количество серверов i-го типа), а c[i] - коэффициенты (в данном случае - стоимости серверов i-го типа). Функция linprog минимизирует эту целевую функцию.
	    
	- **A_ub=A**: Это матрица коэффициентов ограничений-неравенств. A_ub означает "upper-bound", то есть ограничения вида "меньше или равно". В данном коде A - это матрица:
	    
	    $$
	    A = \begin{bmatrix}
	    -powers[0] & -powers[1] \\
	    consumptions[0] & consumptions[1]
	    \end{bmatrix}
	    $$
	    
	    Это означает, что ограничения имеют вид:
	    
	    $$
	    -powers[0] \cdot x[0] - powers[1] \cdot x[1] \leq -users
	    $$
	    
	    $$
	    consumptions[0] \cdot x[0] + consumptions[1] \cdot x[1] \leq max\_consumption
	    $$
	    
	- **b_ub=b**: Это вектор правых частей ограничений-неравенств. Он задает верхние границы для левых частей неравенств, определенных матрицей A_ub. В данном коде b = [-users, max_consumption]. То есть, ограничения имеют вид:
	    
	    $$
	    -powers[0] \cdot x[0] - powers[1] \cdot x[1] \leq -users
	    $$
	    
	    $$
	    consumptions[0] \cdot x[0] + consumptions[1] \cdot x[1] \leq max\_consumption
	    $$
	    Первое неравенство гарантирует, что общее количество обслуживаемых пользователей будет не меньше, чем users (обратите внимание на знак минуса Если бы мы не умножали на -1, linprog интерпретировала бы ограничение неверно (как ограничение сверху, а не снизу). Второе неравенство гарантирует, что общее энергопотребление не превысит max_consumption.
	    
	- **bounds=bounds**: Это ограничения на значения самих переменных. В данном коде bounds = [(0, None), (0, None)]. Это означает, что каждая переменная x[i] должна быть больше или равна нулю (0) и не имеет верхней границы (None). То есть количество серверов не может быть отрицательным. bounds задается в виде списка кортежей, где каждый кортеж соответствует одной переменной и содержит (нижнюю границу, верхнюю границу).
	    
	- **method='highs'**: Это строка, указывающая метод решения задачи. 'highs' выбирает один из современных солверов (решателей) из библиотеки HiGHS (High-performance software for linear optimization).
	    
	- **result**: Это объект, содержащий результаты решения задачи. Он включает в себя следующие атрибуты:
	    
	    - **result.x**: Вектор оптимальных значений переменных (в данном случае - оптимальное количество серверов каждого типа).
	        
	    - **result.fun**: Оптимальное значение целевой функции (в данном случае - минимальная стоимость серверов).
	        
	    - **result.success**: Булево значение, указывающее, было ли найдено оптимальное решение (True) или нет (False).
	        
	    - **result.message**: Строка с описанием результата решения (например, "Optimization terminated successfully" или сообщение об ошибке).
	        
	    - **result.nit**: Количество итераций, выполненных алгоритмом.
3.  **Обрабатывает результат**:
    *   Если решение найдено (`result.success`), округляет количество серверов до целых чисел.
    *   Если решение не найдено, выводит сообщение об ошибке.
4. **Строит график**: Визуализирует допустимую область, ограничения и оптимальное решение.
